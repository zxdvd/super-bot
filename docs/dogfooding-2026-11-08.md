## 真实聊天补充与返工

以一份短篇启动说明验证业务流程，所有请求、补充和返工要求通过原生 Bot 聊天输入：

1. 普通讨论不创建任务；明确先记待办后创建一个缺少范围/验收条件的任务，没有启动 Worker。
2. 下一条聊天补充读者、文件位置、字数与搜索要求，补全原任务并自动安排，没有重复建任务。
3. Worker 实际搜索、写文档、报告；Bot 阅读后回到原对话交付。聊天下载与原文件一致。
4. 自然语言要求调整入口说明和版本对照后，对同一任务返工。运行中显示返工输入已进入上下文，不提供接受运行中成果的操作。
5. Worker 修改同一文件，生成新运行和新成果；Bot 再次阅读并交付。新版 411 个汉字，持久交付事件存在，任务待验收，humanAcceptedAt 仍为空。

最终文件 2131 字节，SHA-256 为 `c150069c9bdb995970a14e36d8f90c9e9151796edb5d4051fe31bed888063840`。新下载 API 返回 200，浏览器实际下载也与原件一致；旧成果下载返回 409，避免将变化后的文件冒充旧版本。任务和本轮 Worker 绑定保持一致，新旧成果编号不同。

## 问题及处理

- 旧 Worker 在新尝试复述旧报告而未执行：派发提示加入本次运行身份及重新核实要求，无工具调用的旧回答未记作成功。
- Worker 询问已经预留的目录：明确调度器已预约资源的事实，程序互斥仍是约束来源。
- 真实 respond 调用的空可选 scope/acceptance 被误判成补全任务：Bot 另派 Worker 修复，提交 `ad73346`。原生 ToolsService/NativeToolExecutor 回归证实空字段来自调用参数，非解析器插入；空字段不再误分流，非空输入保留原校验。
- 文档首轮在尚未执行的写文件工具调用中重复生成文本：外层停止，核对原生会话空闲、文件未创建、无成果，然后解除停止后的绑定，用新 Worker 上下文恢复同一任务并成功。**根因未确定，没有宣称修复 DSH 或模型引擎。**

Node 调整、异常恢复、审核和 HMR 由外层执行；搜索安装、代码修复、工作视图和两轮文档交付由产品 Bot/Worker 执行。本记录不代表完全无人干预。
