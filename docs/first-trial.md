# 第一次真实模型试用

当前验证版本是 DSH Web 0.2.2-rc.1、Node 24.21.0。确定性测试已经覆盖任务状态、真实文件工具和原生审批，但没有评估真实模型的工作质量。此页只列需要你本人账号或判断的最后一段，不要求重新批准已完成的开发工作。

## 准备一个可用模型

按 [README](../README.md) 的独立 home/profile 安装方式启动。不要在日常 DSH profile 上重复执行初始化命令。

创建 Bot，填写它负责的工作。启用管理对话后，打开原生会话，在模型选择器里明确选择模型，并完成该提供方的登录或 API Key 配置。Super Bot 不保存或搬运模型凭证。

未选模型时，管理通知保留且不会消耗自动唤醒次数。新 Worker 会继承 Manager 所选模型；已有会话明确选定的模型保留。只准备了任务会话、没有启用 Manager 时，也可以为该会话选模型，再从工作台手动开始。

原生默认路由不算已选择。明确选择也不保证账号可用：缺凭证、认证失败或额度不足会显示原因，需要到原生设置修复。失败任务仍需核对后恢复，旧输入不自动重发。

## 第一项：本地说明文档

在管理对话发送一个明确请求，例如：

> 创建并安排一个任务：只在本任务专用目录写一份 usage-note.md，解释这个 Bot 能做什么、哪些情况需要我处理。验收要求：文件有标题、能力与限制两节，每节至少两条，并回读实际文件。默认由我最终验收，不执行 Shell，不发布或发送给其他人。

回到工作台检查：有且只有一个任务，目标/范围/验收条件完整；运行时能打开对应原生会话；提交成果后先显示待验收。打开成果文件检查内容，再点击接受。模型说“完成”本身不等于产品已验收。

可以另建一个不同文档任务，观察两个任务各自的会话、目录、报告和待办。全局最多同时执行两项文件任务。

## 第二项：临时样例文件修改

在自己准备的临时样例目录打开一个普通 DSH 会话。不要用重要仓库作为第一次试用对象。在原生会话菜单中复制 Session ID；然后在 Super Bot 创建完整但“先暂停”的任务，将 ID 粘贴到关联表单并检查，分别确认完整历史和所示目录的授权。

关联后仍暂停；核对范围后恢复自动管理。要求模型修改一个明确文件并回读，保留人工最终验收。当前仅开放 read/write/edit 和报告，不会自动执行测试、Shell 或子 Agent；需要编译或测试的结果请你自行核对，不能把文本回读当作测试通过。

## 需要体验的操作

- 在成果待验收时提出一次具体返工要求，确认产生新 Run；旧报告与返工记录保留在原生会话历史。返工可能覆盖同路径文件，需要保留旧文件版本时请自行备份。
- 任务询问必要信息时，从对应待办回答，确认只有进入该次模型上下文后问题才关闭。
- 需要接管时在原生会话输入，确认工作台转为人工接管。旧自动执行不能继续获得工具权限；新人工轮次要等旧执行收敛。
- 停止任务后检查原生会话和文件。若显示待核对，先确认活动与影响，再完成核对；任务保持暂停。
- 关闭工作台后回到原生会话，再重新打开工作台，确认任务与成果仍在。宿主进程退出后的继续执行需要另行核对，不能把浏览器 Panel 与宿主生命周期混为一谈。

## 试用后最有价值的反馈

记录任务 ID、预期行为、实际行为和可复现步骤即可；不要把 API Key 或完整私人聊天贴进问题记录。尤其关注：Manager 是否准确区分普通问答和新任务、验收说明是否与文件一致、等待与恢复提示是否容易理解。

目前后置：真实模型判断质量、Desktop 兼容、最终用户体验确认。精确 Token/费用归因、Shell/子 Agent、外部服务锁、云端部署和独立 App/Web 均不在这个文件任务预览中。
