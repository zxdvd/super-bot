# 第一次真实模型试用

当前聊天主流程已有实现、确定性宿主测试，以及真实模型补充需求、交付和返工记录。本页用于用户亲自试用和最终接受；必要澄清、多任务歧义及交付质量仍需按实际任务判断，不能把局部 dogfooding 当成首版产品验收。

## 开始聊天

按 [README](../README.md) 安装到独立 home/profile，进入左侧 Super Bot。填写名字，点击“创建并聊天”，不需要启用 Manager 或创建任务。职责可留空，参考材料可稍后在“工作与设置”中配置。

在原生模型选择器中明确选择模型，并完成该提供方的登录或 API Key 配置。Super Bot 不保存或搬运凭证。未选模型时通知保留且不会自动执行；账号缺失、额度不足或模型报错时不会无限重试。

## 用一件小事验收

1. 先问“你好，你可以怎么帮我？”，应正常回答且工作列表仍为零。
2. 发送“写一份新同事入职准备清单，保存成 Markdown，包含入职前、第一天和第一周三部分，每部分三项。完成后给我文件。”
3. Bot 应自己归纳必要范围与检查条件、创建一项工作并执行；不要求填写表单、复制会话标识或点击开始。真正缺少必要信息时，应先询问。
4. 暂时离开再返回 Bot，应在原对话看到交付摘要、文件链接、检查情况和待确认状态。点击文件链接，检查实际内容。
5. 在同一对话说“每一项再补一句为什么要做”。应在原任务上返工，完成后再次交付，不应另外新建同目标任务。
6. 点交付中的“查看成果并确认”，应直接打开正确成果详情；检查后点击“接受成果”。只有这次真实点击才记录人工接受。
7. 另试一个会需要补充信息的请求，确保 Worker 的问题返回 Bot 对话；在这里回答后继续执行。存在多个可能对应的任务时，Bot 应先问清楚。

默认 Full Access Worker 使用普通 DSH 会话的原生工具，联网、Shell 和外部服务能力由当前宿主配置决定；显式 `fullAccess: false` 的 files 模式仅开放专用目录内文件工具。试用前核对当前模式和模型配置。失败或文件变更后应显示真实状态，不把“模型说完成”当成验收。

## 异常处理

“工作与设置”保留停止、暂停、原生审批和恢复核对入口。暂停阻止后续派发；停止需要等待实际收敛。重启或投递回执不明时，检查原生会话和文件，再显式完成核对；旧输入不会自动重放。缺模型账号或额度时，先在原生设置处理，再根据当前状态继续。

试用时记录是否顺畅、是否误建任务、是否遗漏说明以及成果是否符合要求。实际聊天和凭证保留在运行数据中，仓库只记脱敏结论。
