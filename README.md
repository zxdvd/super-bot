# Super Bot

持久的 Bot 管理任务、组织执行、检查成果，并通过 Dashboard 让人知道哪里需要自己处理。

**聊天表达意图；面板展示事实；程序维护状态；模型负责判断。**

当前已有本地开发预览：Bot 与任务账本、创建/补全/暂停、搜索分页、独立执行会话。已支持手动派发的文件任务、结构化提问/成果、回答、返工、停止和人工验收；持久 Manager 已可创建任务、安排执行、读取证据并检查成果。首个交付形态是 DSH Web 插件，固定验证版本 `0.2.2-rc.1`；Desktop `0.2.1-rc.5` 尚未完成兼容验证。Super Bot 是独立产品，不属于 `dsh-plugins` 搜索插件集合。

## 产品边界

- Bot 是长期身份；Task 是责任对象；Run 是一次尝试；执行 Session 可以替换。
- 默认人工最终验收；Bot 可以检查证据并提出最多两次自动返工。
- 单用户、单宿主、本地 SQLite；多个 Bot、普通原生任务 Session、需要人工处理的事项优先展示。
- 当前以 DSH 提供模型执行、工具、原生聊天与审批。未来可能成为独立 App/Web；本轮不实现第二个运行时、独立服务器或云端部署。

领域逻辑不依赖 DSH `Context`、Session 类型和客户端组件。DSH 是第一个执行适配与产品入口，不是产品身份；独立 App/Web 仍需另行实现宿主、认证、执行适配和数据迁移，不能承诺只换 UI 即完成迁移。

## 本地开发预览

需要 Node `>=24.9`，当前验证 Node `24.21.0`。在仓库中运行：

```sh
npm ci
npm run check
npm run dev
```

`dev` 使用仓库 `.runtime/dsh` 下的独立 home/profile，监听 `127.0.0.1:3081`。从终端启动链接进入后点击左侧 Super Bot。它不复用日常 DSH 的会话或模型凭证。退出用 Ctrl-C；再次运行保留任务数据。数据库默认在 `$DSH_HOME/super-bot/ledger.sqlite`，不要同时用多个宿主打开同一数据库。

- `npm run check`：类型检查、核心账本测试、Host/Client 构建。
- `npm run smoke`：测试宿主运行时检查真实状态、WAL、未认证访问与跨域拒绝。
- `npm pack --dry-run`：核对分发清单；运行数据和契约测试插件不进入安装包。

Node 用 fnm 管理时，可用 `fnm exec --using=24.21.0 npm run dev`，无需改变机器默认版本。完整执行流程和可靠性门槛见任务清单。创建任务只保存目标；“开始执行”才调用原生会话中选定的模型。当前 Worker 只开放任务目录内的 read/write/edit 和结构化报告，不开放 Shell/子 Agent；每次执行上限 10 分钟，全局最多 2 个未收敛任务。暂停只阻止后续派发，停止会请求取消并核对收敛。


## 当前可试用流程

1. 创建 Bot 和带范围/验收条件的任务，准备独立执行会话。
2. 打开任务会话选择模型，回面板“开始执行”。
3. 遇到问题，保存回答后再次开始；有成果时先检查文件，再接受或保存返工要求。
4. 面板会重新核对文件哈希和执行活动后接受成果。停止后任务保留为暂停。
5. 重启、回执不明或原生介入产生待核对时，检查原生会话和外部效果；明确确认后释放占用，任务保持暂停。旧输入不会自动重放。

这些操作已使用独立测试模型和真实 DSH 文件工具验证，不代表真实模型质量、Shell、后台进程、全部原生审批路径或 Desktop 已验证。测试模型只存在于单独的契约测试插件中，不随产品包交付。


## 持久 Manager

在 Bot 下启用管理对话并选择模型。它可以通过聊天创建任务，也会接收新任务、回答、返工和执行结束的重要事件。仅完整且处于自动管理状态的任务可派发；默认由人最终验收。创建任务时明确授权的低风险任务可由 Bot 验收，记录不会伪装成人工接受。

Manager 只拥有管理工具，不能调用 Shell 或任意文件写入。任务按 Bot 隔离；自动返工最多 2 次，要求第三次时暂停并转人判断。自动管理每 Bot 同时一轮、全局最多两轮；每轮最多 12 步/5 分钟，每 Bot 每小时最多 20 次自动唤醒。进度报告不唤醒 Manager。

“管理会话设置”可在空闲时更换对话。原对话与任务保留，新对话从账本恢复；旧对话不能继续修改任务。返回工作台会保留当前 Bot 选择。
