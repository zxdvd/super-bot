# 飞书群接入同一个 Bot 对话

Status: verified

Scope: super-bot。Context: DSH 宿主。Created: 2026-11-24。

## 目的与范围

在本地 Bot 管理对话和飞书专属群之间接续聊天。宿主启用一个飞书自建应用，通过官方 Node SDK 收发文本。每个 Bot 可选择创建私有群，或预览并绑定已加入的现有群。绑定使用稳定的 Bot ID 和 chat_id；一个群只能属于一个 Bot。群内成员可阅读发到群里的内容；只有配置的个人 open_id 可向 Bot 输入。免 @ 依赖飞书已授予的群消息事件范围。

## 验收标准

- 两个 Bot 同时使用同一个应用，各自只向绑定群投递；改群名或更换管理会话仍按原 Bot 路由。
- 只处理绑定且连接可用后新产生的消息。启用、重新绑定、重启与断线恢复均跳过旧消息。飞书重投、助手中间输出、自动通知以及机器人自身的消息不会产生回声或重复执行。
- 网页真人发言及最终可见回复转发给群；授权的群文本在同一原生 Manager 对话可见，可正常委派、回答和返工。任务最终确认沿用原工作台。
- 解绑立即撤销绑定。密钥留在指定宿主。管理面板呈现绑定群与连接或投递异常。首版覆盖文本，附件、飞书审批、群内多人授权和导入历史留待后续。
- 连接页分别呈现当前凭证换令牌的结果和本人绑定状态。本人主动私聊、机器人成功回发后可确认身份；跳过测试和导入原身份保留各自的事实。
- 各群以本次绑定后接收的授权账号消息验证普通文字和 @ 机器人。超时可按需检查发布权限与订阅，解绑或改绑后重新验证。

## 设计

使用 SQLite 保存绑定和消息凭据。DSH 层用独立的飞书来源和可核对的本端接收凭据认定真人输入。出站仅消费实时事件。开发回归使用合成夹具及隔离宿主。真实租户联调使用已授权账号在专用测试群内核对收发及重绑行为。

预览和确认都核验机器人在群。飞书拒绝机器人查询自身群成员资格的权限时，使用同一个应用身份查询机器人已加入的群列表，精确匹配目标 `chat_id`。授权账号的群成员资格继续由群主字段或群成员接口核验。新建群已保存 `chat_id` 后如暂未确认机器人在群，会短暂重查同一个群。稍后按原群名重试也会继续核验同一个群。
