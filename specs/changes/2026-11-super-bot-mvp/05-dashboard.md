# 05 Dashboard

职责：作为 Bot 聊天的辅助“工作”入口，提供任务、成果、设置和异常控制，支持打开原生执行会话。按 [聊天主流程](06-chat-first.md)，默认入口改为 Bot 对话；本页能力保留，但不要求用户先操作面板才能交代工作或收到交付。此入口调整尚未实现。

本轮不扩建总览分类或管理平台。回答/返工以 Bot 对话为常用入口，原表单保留为确定性辅助操作；人工验收可从聊天成果直接到达确切确认位置，不要求搜索任务。暂停、停止、恢复和原生审批继续复用已有受控入口。

## 确定性查询

主标签优先顺序：停止中/待核对 → 业务终态 → 未解决 Attention → manual/paused → 待 Bot 验收 → 运行/排队 → 有来源的等待 → 未恢复的失败 → 待安排。详情始终展示全部事实。Cancelled 只在停止收敛后成立。

每行展示目标、状态、最新变化、下一步责任人和时间；区分 Worker 自报、Manager 判断与工具证据。没有可计数里程碑不显示百分比，没有连接器不显示“正在监听 CI”。

列表与统计由相同投影/快照版本得出，分页与过滤在应用查询完成。详情按需读摘要、成果与事件；完整工具轨迹留在原生 Session。lastActivityAt、lastProgressAt、lastSyncedAt 各有意义，静默窗口只产生“无新进展”。

## 操作

查询与命令调用应用服务，不由模型解释按钮。每个变更携带 requestId 和所需版本；重复点击安全、冲突明确要求刷新。打开 Session 不改变控制权；暂停、接管、停止本次 Run、取消任务、重试、恢复自动管理分别呈现其语义。

可见时轻量轮询，失焦停止，失败退避；宿主失联保留带时间的过期快照，禁用变更按钮。重连后刷新，不自动重放离线点击。关闭面板不影响后台调度；模型失联不影响已知问题回答和停止请求。

宿主组件与传输封装在 DSH Client 入口。页面主体用可注入命令客户端和导航回调，保留未来 App/Web 复用的可能；不为未来建立第二个 UI 壳。
