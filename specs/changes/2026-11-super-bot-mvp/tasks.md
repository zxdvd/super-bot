# 可逐步推进的任务

本清单是开发任务，不是 Codex 新聊天或飞书待办。每项完成时补实际命令/版本/结果到 evidence；尚未存在的测试命令写作预期交付，不能当作已执行。

## 推进约定

先完成真实边界探针，再构建可测试账本，再接一次人工驱动闭环，最后让 Manager 使用同一套能力。每个任务交付一个可演示变化，不按数据库/后端/前端机械分组。

依赖主线：`SB-01 → SB-03 → SB-04/05 → SB-06 → SB-07/08/09 → SB-10 → SB-11/12 → SB-13/14 → SB-15 → FV`。SB-02 与不执行模型的账本/面板开发交错推进，必须在 SB-06 自动派发前通过必要门槛。SB-12 也依赖 SB-09。用户已要求独立 subagent 反复试用反馈，版本可用后启动试用循环。

HITL 表示验收需要真实用户动作或原生 UI（审批、接管、选定证据），不表示每项开发前都要重新请求批准。

## P0：先证明当前宿主能承载产品

- [x] **SB-01 — 可安装的最小插件和兼容探针入口**
  - 交付：TypeScript 项目与锁定依赖，DSH Host/Client 独立入口；一个显示真实兼容版本的空面板，能打开一个测试 Root Session；明确卸载回收。
  - 同时建立实际 `npm run typecheck`、`npm test`、`npm run build` 与 `npm pack --dry-run`；宿主共享包使用正确 peer/dev 依赖，测试数据不入安装包。可根据验证选用其他包管理器，但同步全部命令。
  - 验证：独立测试 home/profile 安装、启动、导航、禁用、重载；检查工具/监听器没有重复且原生会话保留。真实插件上下文验证 SQLite 文件持久化/WAL，不只测内存。记录宿主启动入口和包哈希。
  - Depends on: SB-00。HITL: 原生面板/会话导航观察。Parallel: 否。

- [ ] **SB-02 — 执行契约探针与支持/降级表**
  - 交付：最小 Fake Adapter 契约与真实 DSH 探针。证明消息身份贯穿入队、准备、持久 user/message；核对停止后 inbox、job、子 Agent；验证 Manager/Worker 工具作用域和原生用户输入识别。
  - 验证：准备阶段取消、重复 requestId、回执丢失、ready 后后台工具仍运行、插件重载、原生审批跳转。优先确定性假模型+真实 DSH 宿主；有必要时用临时目录执行无外部副作用的真实模型任务。
  - 每项输出 supported/limited/unavailable、证据位置与用户可见降级。仅浏览源码不能通过。若无法强制工具范围或确认消息归属，阻止 SB-06 自动派发。
  - Depends on: SB-01。HITL: 原生输入/审批。Parallel: 否。

## P1：用户能看到持久的工作

- [x] **SB-03 — Bot 与未调度任务的持久创建**
  - 交付：SQLite schema/迁移、单宿主控制权、应用命令、幂等、rowVersion/taskRevision、Event/Outbox；创建 Bot 和含验收条件的任务，重启可查询。缺范围时创建澄清事项而不派发。
  - 验证：同请求重复返回同对象、同键异内容拒绝、并发修改冲突、事务回滚没有半条 Task/Outbox、第二宿主不能调度；核心测试不 import DSH。
  - Depends on: SB-01。Parallel: 否。覆盖 T04、T15、T16。无需等待无关的执行探针才能实现纯账本。

- [x] **SB-04 — 可查询的工作台与任务详情**
  - 交付：Bot 页面、创建表单、只读列表/详情、待办优先、统计/筛选/分页、过期快照；初期显示真实未调度任务和明确标识的测试夹具。
  - 验证：100 个混合状态夹具；同一快照的计数与筛选互相核对，任务数与 Attention 数不混算；列表不加载所有聊天。模型不可用仍可查账本，离线禁用变更且不重放。
  - Depends on: SB-03。Parallel: 可与 SB-05 在冻结应用契约后并行。覆盖 T03、T12、T17。

- [x] **SB-05 — 普通 Session 的创建、授权关联与打开**
  - 交付：持久 Binding、创建意图、代数、授权范围、历史绑定；新任务创建独立 Root Session，现有 Session 确认后才关联。UI 展示能力限制。
  - 验证：创建回执丢失不重复建会话、关联已有活跃 Session 不自动派发、跨 Bot 冲突拒绝、解绑保留原会话。部分历史隔离不可实现时测试“新 Session + 明确材料”替代路径。
  - Depends on: SB-02、SB-03。HITL: 关联授权/原生打开。覆盖 T01、T13、T16。

## P2：先由用户驱动完整执行闭环

- [ ] **SB-06 — 一次可追踪且可恢复的派发**
  - 交付：从面板派发一个任务，创建 Run/Input/Outbox，映射真实消息与 turn；Worker 作用域工具；同一 Session 和写目录不双跑。此时可以没有 Manager 模型。
  - 验证：Fake Adapter + 真实 DSH 各跑一次；输入提交后崩溃、投递后回执丢失、重复派发、旧 generation 回调；若无法证明投递结果转 recovery，不能自动重投。
  - Depends on: SB-02、SB-04、SB-05。覆盖 T01、T04、T10、T13。

- [ ] **SB-07 — 从 Worker 报告到可人工验收的成果**
  - 交付：五类结构化报告、证据版本与内容校验、ready 候选、执行收敛门槛、人工接受/拒绝；成果详情解释每项验收条件。
  - 验证：一个临时目录小任务从创建到人工验收；无证据/内容变化/旧 revision/工具未停不能完成；验收与关闭待办同事务；重复报告不重复通知。
  - Depends on: SB-06。HITL: 最终验收。覆盖 T05、T06、T07、T09、T18。

- [ ] **SB-08 — 回答问题与原生审批待办**
  - 交付：Worker 提问、面板回答、Input 的已提交/已投递/已进入上下文状态；原生审批引用与跳转；等待来源明确；重要通知 Outbox。
  - 验证：回答送达正确 Run/版本、准备阶段取消不算已消费、旧问题拒绝；原生拒绝审批后回读状态；通知失败只重试通知。没有审批查询能力时验证明确降级文案与跳转。
  - Depends on: SB-06（验收事项复用 SB-07）。HITL: 回答/原生审批。覆盖 T07、T10、T19。

- [ ] **SB-09 — 暂停、接管、停止、取消和重试**
  - 交付：控制意图持久化；撤回自有待处理输入；等待活动收敛；未知资源占用保留；显式核对后恢复/新 Run。
  - 验证：cancel accepted 但 inbox/后台 job 尚在、停止超时、Failed Run 未释放资源、原生人工输入竞争、目标修改时旧报告晚到；用户消息不得被插件清空。
  - Depends on: SB-06、SB-07、SB-08。HITL: 原生干预/显式恢复。覆盖 T06、T08、T09、T11、T19。

## P3：让 Bot 管理已验证的闭环

- [ ] **SB-10 — 持久 Manager 与任务管理工具**
  - 交付：Bot 管理入口、受限工具、配置版本与知识引用、普通问答/建任务区分、每 Bot 串行管理轮次、重要事件队列。
  - 验证：管理会话替换后列出全部工作；两个 Bot 不能越界；progress 不反复唤醒；Manager 思考期间用户接管/改目标，其迟到命令被拒绝。
  - Depends on: SB-07～09。覆盖 T02、T12、T13、T20。

- [ ] **SB-11 — 基于证据的 Bot 验收与有限返工**
  - 交付：按验收条件保存 Review；最多 2 次自动返工；默认转用户验收；明确授权低风险任务可 Bot 关闭，humanAcceptedAt 保持独立。
  - 验证：真实任务一次返工后再提交；证据不足、额度耗尽、无报告均产生明确待办；重启/换 Manager 不重置次数；旧结果不能自动验收。
  - Depends on: SB-10。HITL: 低风险自动验收设置/人工验收。覆盖 T05、T14、T18、T20。

- [ ] **SB-12 — 多 Bot、多任务与容量预算**
  - 交付：全局/每 Bot 并发、回答/恢复优先、资源规范化与冲突检查、运行预算和公平调度。初始候选：全局 Worker 槽位 2、每 Bot 2、每 Bot Manager 1；管理调用单独计量并受全局预算约束。
  - 不抢占已运行任务；人工回答可先落账，但无容量时明确排队，不能隐含超卖槽位。时间/Token 预算在可测量能力范围内强制，无法精确费用归因则标估算；启用前固定可测试默认值。
  - 验证：一个 Bot 两个任务并行、两个 Bot 竞争容量、目录别名/父子重叠、worktree 共享服务锁、未知执行占位、等待审批不双派发、预算耗尽停止新派发。
  - Depends on: SB-09、SB-10。Parallel: 可与 SB-11 并行（稳定调度契约后）。覆盖 T01、T09、T13、T14、T16。

## P4：故障可靠性与个人试用

- [ ] **SB-13 — 持久化边界的故障注入**
  - 交付：可重复的崩溃/重复/乱序/回执丢失夹具，执行恢复与通知重试分离；已证明未提交的暂时故障才可有界重试。
  - 验证：逐一在命令提交、Session 创建、输入投递、进入上下文、报告、验收、通知前后中断；重载时旧 Agent 活跃；Fake Adapter 全自动，真实宿主至少复现投递回执丢失与停止未收敛。
  - Depends on: SB-11、SB-12。覆盖 T04、T06、T08～T11、T16、T19、T20。

- [ ] **SB-14 — 数据升级、备份与插件生命周期**
  - 交付：schema 升级/拒绝未知版本、SQLite 一致性备份与恢复、产物和 DSH 数据备份范围说明、安装包清单、禁用/卸载与回滚说明。
  - 验证：备份恢复后可核对任务/成果/会话引用；中断迁移不调度；第二宿主拒绝执行；禁用清理工具/监听器且保留用户 Session 和成果；安装包不含凭证/真实日志/数据库。
  - Depends on: SB-12（最终回归依赖 SB-13）。Parallel: 可与 SB-13 分工，不并发修改同一个运行 profile。覆盖 T02、T10、T15、T16。

- [ ] **SB-15 — 真实个人试用与首版验收**
  - 交付：选定目标版本的安装包、本地完整使用说明、支持/降级矩阵、真实路径证据。使用无外发/无发布副作用的两类任务，例如生成本地文档与修改临时样例仓库。
  - 验证：用户从管理对话建任务；两个任务并行；一个提问、一个返工；原生接管/停止；关闭 Panel 后继续；重启恢复；最后人工验收。确认 100 条任务面板仍可检索全部待办。
  - Depends on: SB-13、SB-14。HITL: 实际使用体验及最终确认。覆盖全部适用场景。
