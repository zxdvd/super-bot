# 可逐步推进的任务：先完成聊天交付流程

本清单是开发任务，不是 Codex 新聊天或飞书待办。每项完成时补实际命令/版本/结果到 evidence；尚未存在的测试命令写作预期交付，不能当作已执行。

## 推进约定

2026-11-07 用户确认修正：聊天是主入口，任务面板是辅助入口。当前先推进下面的 CF-01～04；已完成的 SB-00～14 保留为底层实现记录，不重做，也不代表产品体验通过。

当前主线：`现有底层 → CF-01 → CF-02 → CF-03 → CF-04 → SB-15 → FV`。CF-01～03 构成第一次端到端演示，完成后就用真实模型试一项工作，不等扩展能力。用户已要求独立 subagent 反复试用反馈；每个可用纵切都实际试用，不以接口脚本替代产品体验。

HITL 表示验收需要真实用户动作或原生 UI（审批、接管、选定证据），不表示每项开发前都要重新请求批准。

## 当前优先：聊天主流程（实现中）

- [x] **CF-01 — 选中 Bot 就进入聊天**
  - 交付：Bot 列表/返回入口默认打开当前 Bot 对话；首次创建简化为名称与可选职责，直接准备并打开会话。一次性模型引导保留；工作台与设置作为辅助入口。
  - 复用：现有 Manager 准备/绑定/更换和 DSH 原生聊天。先核实原生组件可复用性；不支持内嵌时直接导航原生聊天，不另写聊天壳。
  - 验证：独立 DSH Web 全新 profile，创建 Bot 后不经过“启用 Manager”或任务表单即可输入；返回/重开仍是同一 Bot 对话；未选模型零执行，辅助工作入口可找到。完成类型检查、构建与实际 UI 证据。
  - Depends on: 已完成 SB-05/10。HITL: 首次入口、模型选择体验。Parallel: 否。覆盖 C01、C06。

- [ ] **CF-02 — 自然交代一件事，由 Bot 安排执行**
  - 交付：普通问题直接回答；工作请求由 Bot 澄清必要信息、归纳范围/交付要求并使用既有命令建任务、准备 Worker、派发。用户不填写程序字段，不需要手动开始；接单回复简短说明安排与当前状态。
  - 复用：create/dispatch、模型继承、任务配置快照和执行授权；关联真实原生用户请求来源，不把自动事件当成用户指令。
  - 验证：从聊天分别发送闲聊、缺背景的请求、明确文档请求；闲聊零 Task、缺必要信息时不执行、完整请求只建一项对应任务。重复工具调用不重复创建；越界和不支持的能力不执行。补相关适配测试与真实宿主对话证据。
  - Depends on: CF-01。HITL: 自然交代体验。Parallel: 否。覆盖 C02、C03。

- [ ] **CF-03 — Bot 回到原对话交付结果**
  - 交付：执行后由既有重要事件唤醒 Bot，在当前对话给出可读摘要、可打开的成果入口、检查与未验证事项、待确认状态。失败或需要输入时也回到该对话说明下一步；不能只更新任务表。
  - 复用：Outbox、Worker 报告、证据校验和 Review；不增加第二通知系统，不以持续模型轮询等待 Worker。
  - 验证：只从一句自然语言请求开始，不用 API 预建任务/代派发；等待交付并实际打开成果。离开页面后返回仍可看到交付；重复通知不重复执行，未知投递遵循原恢复规则。完成此项后立即安排一次真实模型端到端试用并记录实际表现。
  - Depends on: CF-02。HITL: 对话交付、成果入口；真实模型需账号。Parallel: 否。覆盖 C03、C04、C06。

- [ ] **CF-04 — 在同一对话补充与返工，明确确认成果**
  - 交付：用户在 Bot 对话回答 Worker 问题、提出一次返工；Bot 路由到正确任务并继续安排。多任务有歧义先澄清。交付处提供确定性验收入口，默认仍由用户确认。
  - 复用：respondAttention/rejectResult/acceptResult 等现有应用命令，仅补受限对话工具/入口。宿主上下文校验实际用户来源、归属、版本；模型不得自填人工身份或代为接受。
  - 验证：一次提问→回答→继续、一次交付→返工→再交付→用户确认；两项等待时不误投，过期问题/成果拒绝，自动通知不能伪造用户回答，重复消息不重复责任。若原生聊天不支持确认按钮，验证直达该成果确认位置的一次跳转，不要求搜索面板。
  - Depends on: CF-03。HITL: 回答、返工、最终点击确认。Parallel: 否。覆盖 C05、C06。

已实现 CF-01～04 所需的最小入口和工具；确定性真实宿主已验证闲聊零任务、接单派发、同对话交付、文件下载、问答与返工。2026-11-08～09 的真实 dogfooding 已验证补充需求、交付和同任务返工；正式用户体验核对、多任务歧义与最终接受仍待完成，相关项保持未勾选，不代表上述功能尚未实现。最新范围见[接手说明](../../../docs/handoff.md)，独立 UI 和验收细节见 evidence。

任务中提到的新增行为测试/证据是预期交付，未执行前不能记录为通过。当前没有需要用户重新决定的阻塞问题；原生聊天/按钮能力在实施时用实际宿主验证，已有明确的最小导航方案。
