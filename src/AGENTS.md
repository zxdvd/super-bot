# 源码约定

- Manager 读取经过身份核对的完整用户消息，结合上文解释指代、否定、修正和授权，调用结构化动作。解析器只读有固定语法的数据，如任务链接、作业 ID 和原生事件。不得用关键词、子串或正则替用户决定是否同意某个动作。
- 动作入口核对实际来源、目标归属、当前版本和该动作需要的授权。选项回复绑定到本人看到的那次提问。Worker 报告、系统通知和引用文本都不能代替本人发出命令。
- 已委托的下一步默认派发。保留阻塞时，要能指出冲突的具体对象或可能重复的操作。历史日志缺口、预览未知、内部通知结束都不能替代这一依据。保存指示后，由宿主跟进到 Worker 实际接收。
- 保持账本、领域类型与宿主解耦。SQLite 负责事务、命令回执、版本和名额。DSH 适配层负责原生输入、执行和事件归属。界面通过查询与命令读写。业务变化落在拥有该状态的模块。
- 外部效果要有对应回执。区分排队与已进入会话、阶段与最终交付、已发起停止与原执行已收敛。交付、验收、恢复分别使用自己的证据。
- 新模块以读者要完成的一件事命名，如原生回执核对或账本迁移。同一状态只有一个写入规则。保持对外命令、重试语义与旧账本兼容。
